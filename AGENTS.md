# Collaboration Preferences

- Explain technical questions from the original problem and fundamental principles. Do not assume that an existing learning note means the user has mastered the topic.
- Write code as explicit, readable steps. Prefer meaningful intermediate variables and ordinary loops over comprehensions, chained transformations, or nested expressions that hide execution order.
- Separate logical steps with blank lines and put long argument lists on multiple lines. Keep simple expressions simple; do not add abstractions just to shorten code.
- Avoid excessive defensive programming. Keep checks for important semantic assumptions, but do not add layers of assertions or equivalent guard clauses to learning experiments.
- Preserve the user's notebook experiments. Keep personal teaching explanations in their Obsidian Vault and implementation/reproducibility documentation in this repository.
